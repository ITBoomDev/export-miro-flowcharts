# Export Miro Flowcharts

Chrome extension (Manifest V3) that exports Miro flowcharts into an LLM-ready text format, Mermaid or JSON.
Miro has no flowchart export, and its public REST API and stable Web SDK return flowchart shapes as
`stencil` with no text. The extension reads the board through the page's own `window.miro`
(`miro.board.experimental`), which does return flowchart shapes with their text.

Goal: a free, open-source tool and a Medium article (itboom.dev) about feeding diagrams to LLMs.
Status: **v0.3.0**. Unit and smoke tests pass on a mocked board. **Not yet verified on a real Miro board.**
Start with the "Verify on a real board" list in `docs/ROADMAP.md`.

The user writes in Ukrainian. Reply in Ukrainian, concisely, with no filler. Code, comments, commits
and docs are in English.

## Commands

The dev toolchain is **Bun** (`bun install` once). Tests still import `node:test`, so they also run on
Node 20+ if needed, but all scripts assume `bun`.

```bash
bun run test       # unit tests (bun test, node:test API), formatter/i18n/settings
bun run typecheck  # tsc over src/ via JSDoc (jsconfig.json, checkJs) — no emit, no build
bun run smoke      # end-to-end: real Chromium + extension + mocked Miro board (needs Chromium, see below)
bun run check      # all three
bun run icons      # regenerate icons/*.png from tools/icons.mjs
bun run zip        # dist/export-miro-flowcharts.zip for the Chrome Web Store (tools/zip.mjs, cross-platform)
```

Smoke test browser: `bunx playwright-core install chromium` once, or `CHROME_PATH=/path/to/chromium`.
Branded Google Chrome 137+ ignores `--load-extension`, so use Chromium or Chrome for Testing.
`HEADED=1 bun run smoke` lets you watch it. Screenshots go to a temp dir, or to `SMOKE_OUT`.

Manual run: `chrome://extensions` → Developer mode → Load unpacked → repo root. After editing, press ↻ on
the extension card. To debug the panel, right-click inside it → Inspect. For the service worker, use the
"service worker" link on the card.

## Hard rules

1. **Functions passed to `chrome.scripting.executeScript({ func })` must be self-contained.** They are
   serialized with `toString()`: no imports, no closures over module scope, no helpers defined outside the
   function. This applies to everything in `extract.js` and to `copyAndToast` in `background.js`.
   They must also return structured-cloneable plain data (SDK items are class instances, so copy the
   fields you need).
2. **`src/format.js` stays pure.** No `chrome.*`, no DOM. It is the tested core and runs in both the
   panel and the service worker. Put new output logic here and cover it with a test.
3. **Every UI string goes through `T()`**, with a key in **all** `DICT` languages. The test
   `every language has every key` fails otherwise. Count strings are plural objects
   (`{ one, few, many, other }`; English needs only `one`/`other`). Output-text strings go in
   `LEGEND` in `format.js`, not in `i18n.js`.
4. **Settings changes need a migration.** Bump `SETTINGS_VERSION` in `settings.js`, extend `migrate()`,
   and add a test in `test/i18n.test.mjs`. Never break stored user templates.
5. **No network requests, no analytics, no remote code.** "Runs locally" is a selling point, and Chrome
   Web Store review depends on it.
6. **Don't widen permissions** without a reason written in `docs/DECISIONS.md`. Current set:
   `scripting`, `storage`, `sidePanel`, `clipboardWrite`, host `https://miro.com/app/board/*`.
7. **No build step, no runtime dependencies.** Vanilla ES modules loaded directly by Chrome — no
   TypeScript compilation, no bundler. Types are JSDoc + `tsc --checkJs` (dev-only). Dev dependencies
   (`playwright-core`, `typescript`, `chrome-types`) never ship. See D11/D12 in `docs/DECISIONS.md`.
8. Before calling a change done: `bun run check` passes, `CHANGELOG.md` is updated, and for releases the
   version is bumped in **both** `manifest.json` and `package.json`.

## Conventions

- 2-space indent, single quotes, semicolons, modern JS (optional chaining, `??=`). Keep functions small.
- DOM access in the panel uses `$()`. Escape anything user- or board-provided with `esc()` before `innerHTML`.
- Panel state is module-level (`S` settings, `raw` cached board, `current` last render). `update()`
  re-renders from cache. `refresh()` re-reads the board.
- Node IDs in outputs are `N1…Nn` in DFS order. Never expose 19-digit Miro IDs unless `includeIds` is set.
- Errors from the page come back as `{ errorCode }` (translated via `err_<code>`) or `{ error }` (raw message).

## Common tasks

- **New output option:** add a default to `DEFAULT_OPTS` (format.js), use it in the formatters, add a control
  `#o-<key>` in panel.html (it binds automatically by id), add the i18n label in all languages, add a test.
- **New output format:** add a function to `FORMATS` with `key/label/fn/ext/mime`, add a button in
  `#seg-format`, and add a test. The smoke test checks that JSON parses.
- **New language:** see "Adding a language" in README.md. The `/add-language` command automates it.
- **Changes to what is read from the board:** edit `pick()` in `extractBoard`, then update
  `mock-board.html` and the fixtures in tests.

## Gotchas

- Frame children have coordinates relative to the frame's top-left (`relativeTo: 'parent_top_left'`).
  `buildGraph` converts them to absolute coordinates. Don't compare raw `x/y` across frames.
- Live mode depends on `miro.board.ui.on('experimental:items:update')`. If events don't register,
  `installWatcher` returns `events: false` and the panel falls back to a full re-read on every selection
  change. That fallback is correct but slower.
- The board name comes from `document.title` with the " - Miro" / ", Online Whiteboard…" suffix removed.
  The real title format is unverified.
- In the smoke test the panel runs as a tab, so `chrome.tabs.query({active})` is patched to point at the
  board tab. Production code must keep using `chrome.tabs.query({ active: true, windowId: winId })`.
- Headless Chrome in a non-UTF-8 locale replaces Cyrillic download names with `download`. The smoke test
  sets `LANG=C.UTF-8`. This is not a product bug.
